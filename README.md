# BeaconNova 基线模型

本仓库用于北京数智创新大赛赛题五“基于多源数据融合的文旅场景舒适度评估与风险超前预警模型与分析”的初版建模。当前版本实现一个可运行、可解释、便于后续扩展的基线模型，用于验证数据链路、特征工程、短时预测、舒适度评分和风险分级预警闭环。

## 项目目标

模型面向八达岭长城景区安检口、票务入园和轨道交通到达数据，完成以下任务：

1. 读取赛题配套数据中的安检口 5 分钟客流、票务入园流水与轨道交通客流。
2. 构建时间特征、日历特征、票务聚合特征、通道历史滞后特征、滚动统计特征和轨道到达冲击特征。
3. 预测未来 30 分钟和 60 分钟的通道人数与平均排队等待时间。
4. 根据预测客流、等待时间、通道负载和包检压力计算舒适度分数。
5. 输出蓝、黄、橙、红四级风险预警结果。

## 模型说明

### 数据读取

当前使用三类数据：

- `表2安检口每5分钟安检数据：security_gate.csv.csv`
  - 核心建模表，包含安检口、通道、通过人数、平均等待时间和包检量。
- `表1入园票务数据表：ticket.csv`
  - 按块读取并聚合为 5 分钟入园量、票种占比、票务通道占比和季节标签占比。
- `表3轨道交通客流表：rail_flow.csv`
  - 入园客流先行信号，按 5 分钟时间窗聚合并构造近 30/60 分钟到达冲击特征。

### 特征工程

主要特征包括：

- 时间特征：小时、分钟、星期、月份、周末、日内 5 分钟序号、正余弦周期编码。
- 日历特征：国庆假期、调休工作日、有效周末、暑期、假期序位、距假期天数。
- 票务特征：当前 5 分钟入园量、近 30/60 分钟入园量、当日累计入园量、票种/通道/季节标签占比。
- 通道历史特征：人数、等待时间、包检量的 1/2/3/6/12 个窗口滞后。
- 滚动特征：15/30/60 分钟滚动均值、最大值。
- 安检口聚合特征：同安检口总通过量、平均等待、通道负载占比。
- 轨道到达特征：当前 5 分钟、近 30 分钟、近 60 分钟轨道客流量。

### 预测模型

当前采用 `HistGradientBoostingRegressor` 作为基线回归模型，分别预测：

- 未来 30 分钟通过人数
- 未来 60 分钟通过人数
- 未来 30 分钟平均等待时间
- 未来 60 分钟平均等待时间

若运行环境缺少对应 sklearn 模型，则自动退化为历史中位数预测器，保证流程可跑通。

### 舒适度与风险等级

舒适度分数为 0-100 分，分数越高表示体验越好。初版综合预测等待时间、预测客流负载、包检压力和短时增长压力。

风险等级采用“固定业务阈值 + 本次预测分位阈值”的混合规则。当前尚未接入点位容量表，固定阈值用于表达绝对风险，分位阈值用于在淡季或低负载样本中保留相对风险排序能力。后续版本会将分位阈值替换为点位级容量阈值和专家校准规则。

| 等级 | 含义 |
|---|---|
| 蓝色 | 轻度关注，舒适度开始下降或负载上升 |
| 黄色 | 明显排队风险，需要提前观察和分流 |
| 橙色 | 高负载或等待时间快速上升，需要启动干预 |
| 红色 | 严重拥堵风险，需要立即处置 |

## 后续计划

1. 引入天气体感因子与舒适度分项解释。
2. 接入点位容量表与索道参数，形成节点级风险阈值。
3. 建立景区点位图谱，把安检口、索道、打卡点和险要路段纳入统一传播模型。
4. 将基线模型升级为 PyTorch 时空序列模型或图神经网络模型。
5. 增加策略仿真模块，比较增开通道、分流引导、运力调整等措施的收益。
