# BeaconNova 基线模型

本仓库用于北京数智创新大赛赛题五“基于多源数据融合的文旅场景舒适度评估与风险超前预警模型与分析”。当前版本为 v0.3.0，在 v0.2 票务聚合与日历特征基础上，进一步接入景区核心点位容量表和南北索道运营参数，形成“短时预测 + 容量约束 + 舒适度评分 + 风险主因解释”的可运行基线。

## 项目目标

模型面向八达岭长城景区安检口、票务入园、轨道交通到达、核心点位承载能力和索道运力数据，完成以下任务：

1. 读取赛题配套数据中的安检口 5 分钟客流、票务入园流水、轨道交通客流、点位容量和索道参数。
2. 构建时间特征、日历特征、票务聚合特征、通道历史特征、轨道到达冲击特征、点位容量压力和索道运力压力。
3. 预测未来 30 分钟和 60 分钟的通道人数与平均排队等待时间。
4. 根据预测客流、等待时间、包检压力、容量压力、索道压力和天气暴露风险计算舒适度分数。
5. 输出蓝、黄、橙、红四级风险预警，并给出主导风险因素。

## 环境要求

建议使用 Python 3.10 及以上版本。最低依赖如下：

```text
pandas
numpy
scikit-learn
xlrd
```

其中 `xlrd` 用于读取赛题提供的 `.xls` 容量表和索道表。当前代码不强制使用 GPU，便于先在普通 CPU 环境验证数据链路；后续接入 PyTorch 时空图模型时再启用 GPU。

## 快速运行

在项目根目录执行完整基线，包括票务大表、点位容量和索道参数：

```powershell
python scripts\run_baseline.py
```

如果只是快速冒烟测试，可跳过票务大表：

```powershell
python scripts\run_baseline.py --skip-ticket
```

也可以跳过容量/索道特征，用于和旧版做消融对比：

```powershell
python scripts\run_baseline.py --skip-facility
```

显式指定数据目录和输出目录：

```powershell
python scripts\run_baseline.py `
  --data-dir "赛题五基于多源数据融合的文旅场景舒适度评估与风险超前预警模型与分析0805" `
  --output-dir outputs\baseline_v0_3
```

## 模型说明

### 数据读取

当前使用五类数据：

- `表2安检口每5分钟安检数据：security_gate.csv.csv`
  - 核心建模表，包含安检口、通道、通过人数、平均等待时间和包检量。
- `表1入园票务数据表：ticket.csv`
  - 按块读取并聚合为 5 分钟入园量、票种占比、票务通道占比和季节标签占比。
- `表3轨道交通客流表：rail_flow.csv`
  - 入园客流先行信号，按 5 分钟时间窗聚合并构造近 30/60 分钟到达冲击特征。
- `八达岭景区核心打卡点位全量承载与服务效率参数总表.xls`
  - 提取核心点位瞬时容量、小时通行能力、停留时长、天气防护和瓶颈风险。
- `南北索道基本情况.xls`
  - 提取索道饱和运力、入口平台容量、合理排队上限和运营折减系数。

### 特征工程

主要特征包括：

- 时间特征：小时、分钟、星期、月份、周末、日内 5 分钟序号、正余弦周期编码。
- 日历特征：国庆假期、调休工作日、有效周末、暑期、假期序位、距假期天数。
- 票务特征：当前 5 分钟入园量、近 30/60 分钟入园量、当日累计入园量、票种/通道/季节标签占比。
- 通道历史特征：人数、等待时间、包检量的 1/2/3/6/12 个窗口滞后。
- 滚动特征：15/30/60 分钟滚动均值、最大值。
- 安检口聚合特征：同安检口总通过量、平均等待、通道负载占比、全系统安检压力。
- 轨道到达特征：当前 5 分钟、近 30 分钟、近 60 分钟轨道客流量。
- 容量与索道特征：点位瞬时容量压力、小时通行压力、瓶颈压力、票务对容量压力、轨道对索道压力、索道平台压力、天气暴露风险。

### 预测模型

当前采用 `HistGradientBoostingRegressor` 作为基线回归模型，分别预测：

- 未来 30 分钟通过人数
- 未来 60 分钟通过人数
- 未来 30 分钟平均等待时间
- 未来 60 分钟平均等待时间

若运行环境缺少对应 sklearn 模型，则自动退化为历史中位数预测器，保证流程可跑通。

### 舒适度与风险等级

舒适度分数为 0-100 分，分数越高表示体验越好。v0.3.0 综合考虑等待压力、预测客流压力、包检压力、短时增长压力、容量压力、索道压力和天气暴露风险。风险等级采用“固定业务阈值 + 本次预测分位阈值”的混合规则，既保留绝对风险含义，也保证在低负载样本中具备排序能力。

| 等级 | 含义 |
|---|---|
| 蓝色 | 轻度关注，舒适度开始下降或负载上升 |
| 黄色 | 明显排队风险，需要提前观察和分流 |
| 橙色 | 高负载或等待时间快速上升，需要启动干预 |
| 红色 | 严重拥堵风险，需要立即处置 |

## v0.3.0 参考结果

在完整数据链路下，v0.3.0 使用 107 个数值特征。最近 21 天时序测试集结果如下：

| 目标 | 预测窗口 | MAE | RMSE | WAPE |
|---|---:|---:|---:|---:|
| 通过人数 | 30 分钟 | 4.1286 | 4.8800 | 0.4628 |
| 等待时间 | 30 分钟 | 0.6204 | 0.7375 | 0.4282 |
| 通过人数 | 60 分钟 | 4.1697 | 4.9179 | 0.4657 |
| 等待时间 | 60 分钟 | 0.6350 | 0.7515 | 0.4368 |

## 后续计划

1. 接入天气实况/预报数据，进一步细化热舒适、降雨和强风条件下的体验评分。
2. 建立景区点位图谱，把安检口、索道、打卡点和险要路段纳入统一传播模型。
3. 将基线模型升级为 PyTorch 时空序列模型或图神经网络模型。
4. 增加策略仿真模块，比较增开通道、分流引导、运力调整等措施的收益。
